# Literature Synthesis

A synthesis tells the user what a set of verified papers jointly establishes, where they disagree, what is missing, and where the user's project would sit. It is built only from papers found and checked under [Literature Search](literature-search.md).

## Read each paper for the same five things

1. **Question and object:** what the paper estimates or explains, in the authors' terms.
2. **Approach:** data and source of variation, or the model and its key assumption.
3. **Main result:** direction and magnitude, with units, for the main specification.
4. **Scope:** population, period, setting; partial or general equilibrium; short or long run.
5. **What was read:** full text, abstract only or metadata only, and which version.

Keep each paper's terms as the authors use them. When two papers use different names for one object, or one name for different objects, say so instead of merging them.

## Build the synthesis

Organize by idea, not by paper:

- **Agreement:** what several papers find, and whether they find it with different data or designs (stronger) or the same ones (weaker).
- **Splits:** where results differ. For each split, check the candidate explanations before naming one: different populations or periods, different estimands (ATE versus LATE, partial versus general equilibrium, short versus long run), different identifying assumptions, measurement, or publication version. A split is often where a new paper can contribute.
- **Mechanisms:** which channels the evidence supports, which are asserted, and which remain untested.
- **Gaps:** questions the papers raise but do not answer, settings not studied, designs not yet used. Phrase a gap relative to the search actually done: "none of the papers found studies X".
- **What to read first:** the two or three papers the user should read if they read nothing else, and why.

## Position a project

When the user has a question or draft, place it against the closest verified papers:

- Name the closest two to five papers and what each does.
- State what the project would add relative to each: a setting, a design, a mechanism, a measure, a model.
- Name the paper a referee is most likely to say already does this, and the honest answer to that objection.
- If the project looks already done, say so directly and suggest how it could differ.

## Labels

Mark the status of each statement where it matters:

- **Paper reports:** the authors' own claims.
- **Assessment:** your judgment of their design, scope or robustness.
- **Inference:** a connection between papers or a proposed gap that no paper states.

Quotations are short (a sentence or less), in quotation marks, with page or section. Everything else is in your own words. Never present a summary of an abstract as a summary of the paper.

## Format

Lead with the answer in two to four sentences: the main finding of the literature, the main split, and where the open space is. Then the structured synthesis. End with the coverage line from the search, so the user knows how complete the picture is.
